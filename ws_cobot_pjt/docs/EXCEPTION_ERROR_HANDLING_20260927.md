## 1. 문서 역할

이 문서는 팀이 파악한 예외·오류의 발생 조건, 시스템 차단 원칙, HMI 표시, 운영자 조치, 구현·검증 상태를 한곳에서 관리한다. 코드 수정이 끝나면 해당 항목의 구현 상태와 검증 근거도 이 문서에 갱신한다.

물리적 위해와 안전대책은 [위험요소 및 안전대책](RISK_AND_SAFETY_MEASURES_20260927.md)에 정리한다. 두 문서가 같은 내용을 반복하지 않도록 안전 문서는 이 문서의 오류 ID를 참조한다.

## 2. 공통 처리 원칙

1. 실패·취소·상태 불명이면 다음 단계에 진입하지 않는다.
2. 정지 요청 접수와 실제 정지 확인을 구분한다.
3. `UNKNOWN`, `STOP_UNCONFIRMED`, `COMMUNICATION_LOST`는 성공이나 정지 완료로 바꾸지 않는다.
4. 힘 한계·통신 불명·정지 미확인은 자동 재시도하지 않는다.
5. 실패·정지 후 자동 HOME 복귀, 자동 재실행, 보호정지 자동 해제, 그리퍼 개방을 하지 않는다.
6. 미리보기·검사·실행은 같은 이미지·측정·프로파일·경로 ID, 버전, SHA-256을 사용한다.
7. 공정 실행 성공과 실제 조각 품질 합격을 별도로 기록한다.
8. HMI에는 기계 판정용 오류 코드와 사람이 이해할 수 있는 설명·조치를 함께 표시한다.

| 현재 작업 확인 | `BUSY`, `REQUEST_CONFLICT`, `RUN_MISMATCH` | 활성 준비·생성·run을 조회하고 중복 요청을 만들지 않음 |
| 자산 재생성 | `HASH_MISMATCH`, `PROFILE_MISMATCH`, `SOURCE_MODE_MISMATCH` | 원본·모드·스냅샷을 확인하고 측정·경로를 새로 생성 |
| 실행 전 검사 실패 | `VALIDATION_FAILED`, `IK_*`, `JOINT_LIMIT`, `SINGULARITY_MARGIN`, `SCENE_REJECTED` | 실행 금지, 실패 위치·관절·작업공간을 수정한 뒤 재검증 |
| 치명·미확인 | `FORCE_LIMIT`, `COMMUNICATION_LOST`, `STOP_UNCONFIRMED`, `UNKNOWN` | 자동 재시도 금지, 실제 로봇·도구·양초 상태를 현장에서 확인 |
| 모션 실패 | `MOTION_NOT_STARTED`, `MOTION_INCOMPLETE`, `TIMEOUT` | 제어권·현재 위치·정지 상태 확인 전 새 모션 금지 |
| 기록 실패 | `STORAGE_ERROR` | 저장소 복구 전 새 작업 금지 |

알 수 없는 오류 코드는 성공으로 해석하지 않고 원문을 보존하며 기본적으로 새 작업을 차단한다.

## 6. 이번 코드 수정 범위

1. FastAPI 입력 검증 오류를 `INVALID_INPUT`과 필드 상세로 반환한다.
2. 프런트가 HTTP 오류 코드와 운영자 조치를 보존·표시한다.
3. 준비·생성·실행 화면에 오류 코드·단계·조치를 표시한다.
4. `ALARM_RAISED/ALARM_CLEARED`를 연결해 활성·해제 알람을 구분한다.
5. 실행 전 깊이·속도·contact mode·정지 제한·프로파일 해시와 차단 사유를 읽기 전용으로 표시한다.
6. REAL/SIMULATION에 맞춰 로봇 관측 안내를 표시한다.
7. 실행 이력에서 공정 결과와 품질 판정을 분리한다.

공통 ROS 타입, 모션 순서, 힘·깊이·속도·J6 값은 이번 수정에서 변경하지 않는다.
